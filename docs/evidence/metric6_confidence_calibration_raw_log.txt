PRIMARY FINDING: fine-tuning on PlantDoc shifted the Disease Agent's confidence distribution down across the board on the 85 held-out PlantDoc test images -- 52/85 images scored >=0.7 confidence on the zero-shot checkpoint (stage*_plantvillage_only.pt) vs. only 4/85 on the deployed fine-tuned checkpoint (stage*_best.pt). Operational consequence: orchestrator/pipeline.py's DISEASE_CONFIDENCE_CUTOFF=0.7 gates treat_now vs monitor, so with the deployed model almost every real prediction on unfamiliar photos now routes to 'monitor' rather than 'treat_now' -- consistent with the confidence-honesty UI mostly showing 'low confidence' during manual testing. A cutoff placed at THIS model's own median confidence (0.364) instead of the fixed 0.7 produces a well-populated split (n=43 vs n=42, accuracy 53% vs 21%) -- whether 0.7 is still the right operating point for this model is an open, unresolved question. 

FOOTNOTE, not a finding: the raw 0.7-cutoff accuracy gap moved +11.48% (zero-shot) -> +39.20% (fine-tuned) on the same 85 images. This number is NOT statistically reliable and should NOT be cited as 'calibration improved' -- the fine-tuned side rests on only n=4 images (95% CI [30%, 95%]), an interval wide enough to be consistent with the true accuracy being anywhere from roughly a quarter to nearly all of that bucket. The honest state of the evidence is: we cannot currently tell whether the 0.7 cutoff is better or worse calibrated after fine-tuning, because too few predictions cross that threshold to say.
